## 3. Changes from the Phase 7A design (and why)

| 7A design | 7B implementation | Reason |
|---|---|---|
| Browser may read `app.*` with the anon key through RLS | No browser database access at all; `anon`/`authenticated` have zero privileges on `app` and `ops` | Smaller attack surface; every read is validated, rate-limited and cached by the server |
| Server reads with the service-role key | Dedicated login roles: `webapp_api` (SELECT on `app` + rate-limit function) and `engine_api` (SELECT on 4 tables) | The service-role key is not needed at runtime; least privilege |
| Supabase client library (PostgREST) | Direct Postgres (postgres.js, psycopg) through the pooler | Works without exposing schemas to the Data API; testable locally without Docker |
| In-handler token bucket | Postgres function `ops.rate_limit_hit` with salted SHA-256 client buckets | Consistent across serverless instances; no raw IPs stored |
| Footprint estimate 60-90 MB | **Measured 137 MB** (app schema incl. indexes; database 146 MB) | Repeated text keys in composite indexes of `forecasts` (64 MB) and `series_history` (44 MB); 29% of the 500 MB Free limit. Optional later reduction: integer surrogate keys |
| Python 3.12 default | Python 3.14 pinned | Same interpreter and library versions that produced Phase 5; Vercel supports 3.14 |
| CSV export from a signed payload | `POST /api/v1/planner/export` re-runs the bounded simulation | No signing secret, nothing stored |
| `studyReference` per series for any frozen scenario | Per-series reference only for the base scenario | Curated per-series Phase 5 results exist only for base; other frozen scenarios are labelled as matched |
| `/api/*` | `/api/v1/*` | Versioned from the start |
| M5 300 = 10/5/40/150/60/35 | As approved | All six Phase 5 representatives included |

Local Windows note: the `&` in the project path breaks npm's `.cmd` shims, so local commands call tools through
`node node_modules/...`. Vercel builds on Linux and is unaffected.

## 5. Running the local stack

```bash
cd apps/web && node scripts/local-db.mjs            # terminal 1: Postgres 17.11 on 127.0.0.1:54329
cd apps/web && node scripts/db-reset.mjs            # schema + local-only role passwords
WEBAPP_OWNER_DATABASE_URL=postgresql://postgres:local-owner-only@127.0.0.1:54329/webapp \
  apps/engine/.venv/Scripts/python.exe apps/web/supabase/seed_database.py
cd apps/engine && ENGINE_SHARED_KEY=local-test-engine-key-0123456789abcdef0123 \
  ENGINE_DATABASE_URL=postgresql://engine_api:local-engine-only@127.0.0.1:54329/webapp \
  .venv/Scripts/python.exe -m uvicorn main:app --port 8787           # terminal 2
cd apps/web && node node_modules/vitest/vitest.mjs run               # API gates
cd packages/inventory_core && ../../apps/engine/.venv/Scripts/python.exe -m pytest tests   # S gates
.venv/Scripts/python.exe -m intelligent_demand.bi.webapp_qa          # data gates
```

The local passwords above exist only for the embedded test server; `db-reset.mjs` refuses any non-local host.
